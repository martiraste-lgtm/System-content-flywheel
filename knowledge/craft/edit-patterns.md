# Edit Patterns — cosa Stefano cambia nelle bozze (loop di apprendimento)

> Il sistema impara già dagli **autori di riferimento** (`../references/`) e dalle **performance dei post**
> (`../posts/`). Gli manca un terzo segnale, il più diretto: **come Stefano corregge le bozze generate.**
> Git versiona tutto → il diff tra draft AI e versione editata è materiale di training gratuito.
>
> Adattato dallo Stage 4 (Editor) del sistema GTM Strategist: tracciano il diff e lo reiniettano nelle regole.

Ultima revisione: 2026-05 (struttura creata, da popolare).

---

## Workflow

Quando Stefano edita una bozza e dice *"registra i miei edit"* (o *"cosa ho cambiato"*):

1. Calcolo il diff git tra la versione generata e quella editata (o tra due commit/bozze).
2. Classifico le modifiche ricorrenti: frasi riscritte, claim ammorbiditi/rafforzati, sezioni ristrutturate,
   parole tagliate, esempi aggiunti/rimossi.
3. Registro il pattern qui sotto.
4. Quando un pattern di edit si ripete **3+ volte** → diventa una regola: la propago in
   `../foundation/voice-guide.md` (se è voce) o in `writing_techniques.md` (se è craft).

---

## Formato entry

```
### E[n] — [Cosa Stefano cambia sistematicamente]
**Osservato:** [n volte, su quali pezzi]
**Edit tipico:** [da → a]
**Perché (ipotesi):** [cosa segnala questa correzione sulla voce/sostanza]
**Status:** osservazione (1-2) / regola candidata (≥3) / promossa a voice-guide o craft
```
